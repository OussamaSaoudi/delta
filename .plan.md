# DSv2 State Machine Integration Plan

## Overview

Replace direct FFI approach with state machine-based architecture. Scan files come from executing PARTIAL_RESULT phases as `FilteredColumnarBatch`, not separate FFI functions.

## Clean Builder API

```java
// Build snapshot (state machine hidden)
Snapshot snapshot = Snapshot.forPath(tablePath, executor);

// Query snapshot
StructType schema = snapshot.getSchema();
long version = snapshot.getVersion();

// Build and execute scan (lazy iterator)
Scan scan = snapshot.scanBuilder()
    .withPredicate(predicate)  // optional
    .build();

CloseableIterator<FilteredColumnarBatch> scanFiles = scan.execute();
while (scanFiles.hasNext()) {
    FilteredColumnarBatch batch = scanFiles.next();
    // Extract file metadata from batch columns
}
scanFiles.close();
```

## Phase 1: Core Implementation

### 1.1 Update Snapshot.java

- Static builder: `Snapshot.forPath(tablePath, executor)`
- GC cleanup via `.reinterpret(Arena.ofAuto(), cleaner)`
- Instance methods: `getSchema()`, `getVersion()`, `getTableRoot()`, `getPartitionColumns()`
- `scanBuilder()` returns `ScanBuilder`

### 1.2 Create ScanBuilder.java

- `withPredicate(pred)` for optional predicate
- `build()` returns `Scan`

### 1.3 Update Scan.java

- `execute()` returns lazy `CloseableIterator<FilteredColumnarBatch>`
- Iterator drives state machine on-demand
- Extracts scan files from PARTIAL_RESULT phases

### 1.4 ScanStateMachine (No Changes)

- Remains simple - just returns scan handle
- No collection logic needed

## Phase 1.5: Test Against Real Tables (GATE)

### Ground Truth Comparison with Kernel Java

Use `io.delta.kernel.Table`, `io.delta.kernel.Snapshot`, and `io.delta.kernel.Scan` from `kernel-api` as ground truth:

```java
// Ground truth using Kernel Java API
io.delta.kernel.Table kernelTable = io.delta.kernel.Table.forPath(engine, tablePath);
io.delta.kernel.Snapshot kernelSnapshot = kernelTable.getLatestSnapshot(engine);
io.delta.kernel.Scan kernelScan = kernelSnapshot.getScanBuilder(engine)
    .withFilter(engine, predicate)
    .build();
CloseableIterator<FilteredColumnarBatch> kernelScanFiles = kernelScan.getScanFiles(engine);

// Our implementation
Snapshot ourSnapshot = Snapshot.forPath(tablePath, executor);
Scan ourScan = ourSnapshot.scanBuilder().withPredicate(predicate).build();
CloseableIterator<FilteredColumnarBatch> ourScanFiles = ourScan.execute();

// Compare results
assertSnapshotsMatch(kernelSnapshot, ourSnapshot);
assertScanFilesMatch(kernelScanFiles, ourScanFiles);
```

### Test Cases

1. **Snapshot Comparison** (`SnapshotComparisonTest.java`)
   - Compare version numbers
   - Compare schemas (field names, types, nullability)
   - Compare partition columns
   - Compare table roots

2. **Scan Files Comparison** (`ScanFilesComparisonTest.java`)
   - Same number of files
   - Same file paths
   - Same file sizes
   - Same modification times
   - Same deletion vector info (if present)
   - Same partition values (if partitioned)

3. **Predicate Pushdown Comparison** (`PredicatePushdownTest.java`)
   - Test various predicates (equality, comparison, logical AND/OR)
   - Verify same files returned after pushdown
   - Verify partition pruning matches

4. **Performance Comparison** (`PerformanceComparisonTest.java`)
   - Compare snapshot construction time
   - Compare scan construction time
   - Compare scan file iteration time
   - Should be within 20% of Kernel Java performance

5. **Lazy Iteration Test** (`LazyIterationTest.java`)
   - Verify doesn't load everything into memory
   - Test early termination
   - Compare memory usage vs Kernel Java

**GATE**: All comparisons must match Kernel Java results before proceeding to Phase 2!

## Phase 2: Spark Integration

### 2.1 Update DeltaTable.scala

- Use `Snapshot.forPath(path, executor)`
- Use snapshot instance methods

### 2.2 Update DeltaScanBuilder.scala

- Build scan via `snapshot.scanBuilder().withPredicate().build()`

### 2.3 Update DeltaScan.scala

- Execute scan: `scan.execute()`
- Iterate `FilteredColumnarBatch` results
- Extract file metadata from batch columns
- Convert to `RustScanFileRow` for JSON serialization

## Key Decisions

1. **Scan files from PARTIAL_RESULT** - no separate FFI
2. **GC-based cleanup** - no manual close() 
3. **Builder pattern** - hide state machines
4. **Lazy iteration** - on-demand state machine advancement
5. **FilteredColumnarBatch** - direct from state machine, no wrapper classes
6. **Ground truth testing** - compare with Kernel Java APIs from `kernel-api`
